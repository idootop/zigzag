# Zigzag

**体积更小，画质如初**

一款面向本地归档的多媒体批量压缩工具，在肉眼无损的前提下<br/>把照片、视频与音频压到原体积的两成上下（[实测](#实测)）。

## 背景

移动硬盘中归档的照片与视频，多数由早期设备生成，采用今天看来效率偏低的编码格式，占用了大量本可释放的空间。而现有的批量压缩方案往往在三个方面存在不足：处理耗时长、画质损失不可控、任务中断后无法恢复。更重要的是，多数工具在压缩完成后即覆写或删除原文件，一旦出错便不可挽回。

Zigzag 的目标是让归档整理变成一个可预期、可中断、可回滚的过程：导入目录，查看预估收益，确认后执行，随时可以关机，下次打开继续。

## 特性

- **三条独立管线** — 图片、视频、音频分别采用经基准测试验证的编码参数
- **短边约束缩放** — 以短边为基准的统一缩放规则，长截图、竖拍照片、全景图均能正确处理
- **动图一并处理** — GIF / APNG / 动画 WebP 转为动画 AVIF，实测省 45%~87%（差别来自源本身，色彩越少的 GIF 越难再压）
- **断点续传** — 处理进度持久化至 SQLite，自动跳过已完成文件。异常退出或主动停止后重新打开，队列页直接摆出上次的进度与一个「接着跑」，输出目录不必再选一遍（十万文件实测：恢复耗时 202 毫秒）
- **先扫描，后处理** — 执行前给出体积分布、预计节省空间与预计耗时，确认后再开始
- **跳过无收益文件** — 自动识别已充分压缩的文件，避免无效处理与二次劣化
- **重复文件清理** — 三级比对（文件大小 → 采样哈希 → BLAKE3 全量校验），识别硬链接，删除进入回收站
- **找出相似图片** — 感知哈希识别同一张照片的不同版本（改过尺寸、重新导出、加过滤镜），逐组显示相似度，**默认一个都不勾选**，删哪份由你决定
- **压缩前后对比** — 拖动分界线左右对照画面，下方并排列出体积、分辨率、编码格式与码率；视频两侧截取同一时刻，音频直接看码率变化
- **产物文件名可自定义** — `{name}` / `{srcext}` / `{ext}` 三个占位符，设置界面实时预览效果；只改文件名，目录层级始终与源目录一一对应。`{name}_{srcext}.{ext}` 可以把 `IMG_0001.HEIC` 与 `IMG_0001.JPG` 这类同名不同格式的照片分开
- **开跑前先算空间** — 输出盘装不下就当场拦住，并直接告诉你需要多少、还剩多少，不必等跑到一半才发现
- **说清哪些东西不会被复制** — 输出目录只放媒体文件，报告里会点名文档、`.xmp` / `.aae` 编辑记录与照片图库包各有多少个。打算用输出目录替换源目录的话，你会提前知道要另外备份什么

## 实测

下面的数字全部来自**发布前验收基准**（[PROGRESS.md · ADR-021 §17](PROGRESS.md)）：跑的是打包好的 `.app`、默认档，不是手搓的 ffmpeg 命令——因为调度、短边规则、无收益跳过、元数据保留、完整性校验这些事只在完整管线里才发生。机器是 Apple M1 Max（10 核）/ macOS 15.7.4。

**体积**（20 个文件 / 109 MB）：

| 类型 | 压到原体积的 | 说明 |
|---|---|---|
| **照片** | **14.3%** | 含 HEIC / JPEG / PNG / 长截图，含 Display P3 与 CMYK |
| **视频** | **21.3%** | 手机录像、屏录、高动态素材 |
| **音频** | **14.3%** | FLAC / MP3；已是 AAC 的源只换容器，体积几乎不变 |

> **这三个数比整体那个数更可信。** 整体压缩率是 19.4%，但这份语料里视频占了 75% 的字节，而真实归档盘上照片才是主力——**整体数会随语料构成漂移，分类型的不会**。语料本身也是按「格式覆盖」挑的（31 个文件，每一个对着一条会分岔的处理路径），不是按数量规模挑的，所以它验的是「每条路都走对了」，而不是「平均能省多少」。你自己的盘上会得到什么数，扫描阶段会先给一个区间——本次预估 21.9 MB 产物 / 省 87.4 MB（区间 68.1 ~ 94.1 MB），实测 21.2 MB / 省 88.0 MB，落在区间内。

> 顺带一提：应用里所有体积数字都是 **1000 进制**，和 Finder「显示简介」显示的数字一致，可以直接对着核。

**短边规则**（逐张读产物真实像素核对）：6528×3680 的相机原片 → 1916×1080；3024×4032 的竖拍照片 → 1080×1440 且旋转已烘焙进像素；**750×30000 的长截图一个像素都不动**——短边已经低于上限，按长边限制的工具会把它压成 27 px 宽的一条线。

**质量**：视频 VMAF **96.0 ~ 98.8 分**（四个样本，兜底闸门是 80 分）；图片 SSIMULACRA2 真实照片**全部 ≥ 79 分**（90 ≈ 视觉无损，70 ≈ 高质量），最低的两个 66 分是同一张人造彩条测试图，不是照片。已是 AAC 的音频抽出裸流比对，**逐字节相同**——确认只换了容器，没有重新编码。

**耗时与占用**：109 MB / 20 个文件跑 **29 秒**（≈ 0.23 GB/分钟），CPU 峰值 803%。内存空载 26 MB、跑动时稳态 68 MB、峰值 765 MB——**峰值由同时处理的文件数决定，不由队列长度决定**，所以十万文件的任务不会比这更高（那一轮实测峰值反而更低）。

**同一份输入跑两遍，产物逐字节相同。**

## 数据安全

本项目将数据安全置于其他一切目标之上，具体体现为三条设计原则：

| | 原则 | 说明 |
|---|---|---|
| **P1** | 数据安全优先 | 原文件在产物通过完整性校验前不会被删除或覆写。宁可不压缩，不可压坏。 |
| **P2** | 压缩率不妥协 | 任何以体积换速度的选择都需有明确依据，默认档位不牺牲压缩率。 |
| **P3** | 可中断、可恢复 | 十万级文件的任务可随时中止并恢复，每个文件的处理结果均有记录可查。 |

默认输出至镜像目录，原文件保持不变，回滚操作即为删除输出目录。原地替换需显式开启，且删除操作统一经过回收站。

## 默认策略

| 类型 | 目标格式 | 关键参数 |
|---|---|---|
| **图片** | AVIF | 短边上限 1080、质量 85、4:4:4 色度；一律有损；EXIF / XMP 原样照搬，ICC 始终保留，旋转信息烘焙进像素 |
| **视频** | HEVC（x265） | 短边上限 1080、帧率上限 30、CRF 24、8-bit；默认软编，硬件编码作为「极速」预设可选 |
| **音频** | AAC-LC（`.m4a`） | 码率上限 128 kbps，继承源采样率；AAC 源仅更换容器，不重新编码 |

两道落地闸门同样有默认值：**产物至少要省下 20%**（省得比这少就保留原文件——改写一个归档文件本身是有代价的），**视频产物 VMAF 低于 80 分直接丢弃**（这是兜底线而非画质目标：默认参数[实测](#实测) 96.0~98.8 分，80 分以下基本只剩编码出岔子的情况）。

以上参数均可调整，并提供三档预设（省空间 / 均衡 / 极致画质）与折叠式高级设置。默认路径无需任何配置。

> 上述默认值来自 Apple M1 Max 上的实测基准，包含 VMAF / SSIMULACRA2 评分、体积与耗时的横向对比，完整数据见 [PROGRESS.md · ADR-001 / ADR-004 / ADR-005](PROGRESS.md)。这些基准验证的是**单点参数选得对不对**；整机端到端的数字在上面的[实测](#实测)一节，出处是 [PROGRESS.md · ADR-021 §17](PROGRESS.md)。

## 技术栈

基于 **Tauri 2 + Rust**，空载内存占用实测约 26 MB，跑动时稳态约 68 MB（口径是 macOS 的 `phys_footprint`，也就是活动监视器「内存」那一列；`ps` 报的 RSS 在这台机器上会虚报 15 倍，不可用）。大规模目录遍历与哈希计算采用 `jwalk` + `rayon` + `blake3`。

安装包（`.dmg`）约 65 MB，其中自身二进制只有 18 MB，其余几乎全部是随包携带的 ffmpeg 与 ffprobe。这两个静态构建刻意未做裁剪——归档盘上真正需要它们的，恰恰是那些冷门的早期编码格式。

- **前端** — React 19、Vite、TypeScript、Tailwind 4、shadcn/ui、TanStack Virtual
- **后端** — Rust、tokio、rusqlite（WAL 模式）、image、fast_image_resize、libavif
- **编解码** — ffmpeg / ffprobe sidecar，macOS 平台叠加 ImageIO 与 VideoToolbox

v1 优先支持 macOS（Apple Silicon）。核心逻辑与平台相关代码已分层解耦，后续扩展至其他平台无需重构。

> [!IMPORTANT]
> **首次打开需要手动放行。** 本项目不上架 App Store、也不做 Apple 公证，安装包采用本地自签名，因此 macOS 会提示「Apple 无法验证……是否包含恶意软件」。macOS 15 起，那个对话框上**已经没有「打开」按钮**，早年流传的「右键 → 打开」不再有效。放行方式二选一：
>
> - 前往**系统设置 → 隐私与安全性**，在底部点击「仍要打开」；
> - 或在终端执行 `xattr -dr com.apple.quarantine /Applications/zigzag.app`。
>
> 只需操作一次，之后正常双击即可。
