# Zigzag

**体积更小，画质如初**

一款面向本地归档的多媒体批量压缩工具，在肉眼无损的前提下<br/>将照片、视频与音频压缩至约 1/3 体积。

## 背景

移动硬盘中归档的照片与视频，多数由早期设备生成，采用今天看来效率偏低的编码格式，占用了大量本可释放的空间。而现有的批量压缩方案往往在三个方面存在不足：处理耗时长、画质损失不可控、任务中断后无法恢复。更重要的是，多数工具在压缩完成后即覆写或删除原文件，一旦出错便不可挽回。

Zigzag 的目标是让归档整理变成一个可预期、可中断、可回滚的过程：导入目录，查看预估收益，确认后执行，随时可以关机，下次打开继续。

## 特性

- **三条独立管线** — 图片、视频、音频分别采用经基准测试验证的编码参数
- **短边约束缩放** — 以短边为基准的统一缩放规则，长截图、竖拍照片、全景图均能正确处理
- **动图一并处理** — GIF / APNG / 动画 WebP 转为动画 AVIF，实测可省约 87%
- **断点续传** — 处理进度持久化至 SQLite，异常退出后重新打开可继续，自动跳过已完成文件
- **先扫描，后处理** — 执行前给出体积分布、预计节省空间与预计耗时，确认后再开始
- **跳过无收益文件** — 自动识别已充分压缩的文件，避免无效处理与二次劣化
- **重复文件清理** — 三级比对（文件大小 → 采样哈希 → BLAKE3 全量校验），识别硬链接，删除进入回收站
- **压缩前后对比** — 体积、分辨率、编码格式与码率对照展示，图片支持滑块对比

## 数据安全

本项目将数据安全置于其他一切目标之上，具体体现为三条设计原则：

| | 原则 | 说明 |
|---|---|---|
| **P1** | 数据安全优先 | 原文件在产物通过完整性校验前不会被删除或覆写。宁可不压缩，不可压坏。 |
| **P2** | 压缩率不妥协 | 任何以体积换速度的选择都需有明确依据，默认档位不牺牲压缩率。 |
| **P3** | 可中断、可恢复 | 十万级文件的任务可随时中止并恢复，每个文件的处理结果均有记录可查。 |

默认输出至镜像目录，原文件保持不变，回滚操作即为删除输出目录。原地替换需显式开启，且删除操作统一经过回收站。

## 默认策略

| 类型 | 目标格式 | 关键参数 |
|---|---|---|
| **图片** | AVIF | 短边上限 1080、质量 85、4:4:4 色度；一律有损；EXIF / XMP 原样照搬，ICC 始终保留，旋转信息烘焙进像素 |
| **视频** | HEVC（x265） | 短边上限 1080、帧率上限 30、CRF 24、8-bit；默认软编，硬件编码作为「极速」预设可选 |
| **音频** | AAC-LC（`.m4a`） | 码率上限 128 kbps，继承源采样率；AAC 源仅更换容器，不重新编码 |

两道落地闸门同样有默认值：**产物至少要省下 20%**（省得比这少就保留原文件——改写一个归档文件本身是有代价的），**视频产物 VMAF 低于 80 分直接丢弃**（这是兜底线而非画质目标：默认参数实测在 96 分以上，80 分以下基本只剩编码出岔子的情况）。

以上参数均可调整，并提供三档预设（省空间 / 均衡 / 极致画质）与折叠式高级设置。默认路径无需任何配置。

> 上述默认值来自 Apple M1 Max 上的实测基准，包含 VMAF / SSIMULACRA2 评分、体积与耗时的横向对比，完整数据见 [PROGRESS.md · ADR-001 / ADR-004 / ADR-005](PROGRESS.md)。
>
> 这些基准验证的是**单点参数选得对不对**。整机端到端的耗时 / 质量 / 体积数字（含开头的「约 1/3 体积」）由发布前的**验收基准**给出，见 [PROGRESS.md · §12.1](PROGRESS.md)，届时本页数字会按实测回填。

## 技术栈

基于 **Tauri 2 + Rust**，安装包约 15 MB，空载内存占用约 80 MB。大规模目录遍历与哈希计算采用 `jwalk` + `rayon` + `blake3`。

- **前端** — React 19、Vite、TypeScript、Tailwind 4、shadcn/ui、TanStack Virtual
- **后端** — Rust、tokio、rusqlite（WAL 模式）、image、fast_image_resize、libavif
- **编解码** — ffmpeg / ffprobe sidecar，macOS 平台叠加 ImageIO 与 VideoToolbox

v1 优先支持 macOS（Apple Silicon）。核心逻辑与平台相关代码已分层解耦，后续扩展至其他平台无需重构。
